# DRIVE AI

AI 드라이브 코스 추천 서비스. Next.js + TypeScript + Tailwind + OpenAI + OpenStreetMap(Leaflet) 기반.

## 이전 코드에서 무엇을 바꿨나

버튼을 눌러도 반응이 없거나 "서버 응답이 비어 있습니다" 에러가 나던 원인은 정확히 특정하기 어려웠지만
(터미널 로그를 못 봤기 때문), 재발 가능성이 가장 큰 지점들을 아예 안전한 방식으로 다시 짰습니다.

1. **`openai.responses.create()` (Responses API + strict json_schema) → `openai.chat.completions.create()` (JSON 모드)로 변경**
   Responses API는 openai 패키지의 비교적 최신 버전에서만 지원되고, strict 모드는 요구 조건이 까다로워
   패키지 버전이나 모델이 살짝만 안 맞아도 조용히 실패하기 쉽습니다. Chat Completions + `response_format: {type: "json_object"}`는
   훨씬 오래되고 검증된 방식이라 실패 지점이 줄어듭니다. 대신 AI 응답이 스키마를 100% 보장하지 않으므로
   `validateAIResult()` 함수로 직접 형태를 검증하도록 했습니다.
2. **API 라우트가 어떤 경우에도 빈 응답을 주지 않도록 모든 실패 지점에 `NextResponse.json(...)`을 명시**
3. **프론트엔드에서 `response.text()` 대신 `response.json()`을 바로 쓰고, 파싱 실패 시 status 코드까지 에러 메시지에 포함**
4. **모든 단계에 `console.log`/`console.error`를 남겨서, 터미널만 보면 어디서 멈췄는지 바로 보이게 함**

카페/주유소 경유지 추천, 카카오내비 완전 연동, 음악 API 연동은 아직 자리만 잡아둔 상태입니다(핵심 흐름부터 안정화한 뒤 확장 예정).

## v2에서 추가된 것

1. **장소 검색 실패 대응**: AI가 만든 구체적 명소명이 OpenStreetMap에 없는 경우, 더 넓은 지역명(`regionQuery`)으로 자동 재검색합니다. 그래도 못 찾으면 "인근 지역 기준" 배지가 붙습니다.
2. **코스별 비교 정보 추가**: 편도/왕복 거리, 예상 이동 시간, 예상 주유비(연비×유가), 예상 통행료(참고용 추정치), 목적지 주변 카페/맛집 3곳까지 추천 카드마다 표시합니다.
3. 주유비/통행료는 실제 요금이 아닌 **참고용 추정치**입니다 (전국 평균 유가 기준, 통행료는 거리 비례 근사치). 화면과 API 응답에 안내 문구가 함께 나갑니다.

## v3에서 추가된 것

1. **실제 도로 거리/시간 반영**: 직선거리 추정 대신 OSRM(무료, API 키 불필요) 라우팅 서비스로 실제 도로 기준 거리·시간을 계산합니다. OSRM 조회가 실패할 때만 직선거리로 대체합니다. 이로 인해 주유비 추정치의 정확도가 크게 올라갑니다 (통행료는 여전히 거리 비례 근사치입니다 — 정확한 통행료는 구간별 요금표가 필요해 별도 유료 API 없이는 한계가 있습니다).
2. **내비게이션 버튼을 API 키 없이 작동하도록 교체**: 카카오 SDK(앱 키+도메인 등록 필요) 의존을 없애고, 카카오맵 공식 웹 링크(`map.kakao.com/link/to/...`)로 바로 여는 방식으로 바꿨습니다. 네이버지도도 검색 링크로 즉시 열립니다. TMAP은 공식 웹 딥링크가 없어 검색 결과 페이지로 연결됩니다(모바일 앱에서 가장 안정적으로 동작).
3. `NEXT_PUBLIC_KAKAO_JAVASCRIPT_KEY` 환경변수와 카카오 SDK 로딩 코드를 제거했습니다 — 더 이상 필요 없습니다.

## v4에서 정리한 것 (UI 옵션 전수 점검)

버튼/토글이 실제로 결과에 영향을 주는지 하나씩 점검했습니다.

- **연료 종류**: 이전엔 휘발유/경유/LPG만 주유비 계산이 됐고 하이브리드/전기/수소는 선택해도 아무 효과가 없었습니다. → 전기(원/kWh 충전 단가)·수소(원/kg)까지 전부 실제 비용 계산에 반영되도록 고쳤습니다. 연비 입력란의 단위도 연료 종류에 맞게 바뀝니다 (km/L, km/kWh, km/kg).
- **주변 카페 표시**: 기존에도 실제로 동작했습니다 (그대로 유지).
- **주변 주유소 표시 / 주변 주차장 표시**: 토글만 있고 실제 검색은 하지 않던 기능이었습니다 → 카페와 동일한 방식으로 목적지 주변을 실제 검색하도록 연결했습니다.
- **화장실 / 반려동물 / 톨비 최소 토글은 삭제**했습니다. 무료·키 없는 데이터로는 이 세 가지를 신뢰성 있게 반영할 방법이 없어서(공공화장실 OSM 데이터 부족, 반려동반 여부 실시간 검증 불가, 무료 라우팅 엔진의 통행료 회피 옵션 미지원), 켜도 아무 효과가 없는 상태로 두는 대신 제거했습니다.

## v5에서 추가된 것

1. **TMAP API 연동 (핵심 변경)**: `.env.local`에 `TMAP_API_KEY`를 넣으면:
   - 지도에 **실제 도로를 따라가는 경로**가 그려집니다 (기존엔 출발지-목적지를 잇는 직선이었습니다).
   - 장소 검색이 OpenStreetMap 대신 TMAP POI 검색을 먼저 시도해서 훨씬 정확하고 빠릅니다.
   - Nominatim의 "초당 1건" 제한이 없어져서 **3개 코스를 병렬로 처리** — 추천 속도가 크게 빨라집니다.
   - 키를 비워두면 기존처럼 OpenStreetMap + OSRM으로 동작합니다 (더 느리고, 장소를 못 찾는 경우가 상대적으로 많습니다).
2. **YouTube Music 실제 연동**: "AI DRIVE DJ"의 음악 검색창과 "이 무드 재생" 버튼이 이제 `music.youtube.com` 검색 결과를 실제로 새 탭에 엽니다 (API 키 불필요, 공개 검색 URL 사용).
3. **TMAP 버튼 관련 참고사항**: TMAP은 카카오맵(`map.kakao.com/link/to`)처럼 API 키 없이 경로를 바로 열어주는 공식 웹 링크가 없어서, TMAP 버튼은 여전히 검색 페이지로 연결됩니다. 대신 위 1번 덕분에 **우리 지도 자체에 TMAP의 실제 도로 경로가 표시**되므로, 이 부분이 실질적으로 더 중요한 개선입니다.

## v6에서 정리한 것

- **"인근 지역 기준" 폴백 제거**: 이전엔 AI가 만든 구체적 명소를 못 찾으면 군/읍 단위 중심점으로 대체 표시했는데, 이건 실제 드라이브 목적지로서 의미가 없었습니다. 이제는 AI가 처음부터 **searchQuery/altSearchQuery 둘 다 실제 존재하는 구체적 명소명**(예: "간절곶", "임진각 평화누리공원")을 내도록 프롬프트를 강화했고, 둘 다 지도에서 못 찾으면 그 코스는 아예 결과에서 제외합니다 (3개 중 2개만 나올 수도 있습니다 — 어설픈 장소보다 낫습니다).
- TMAP API 키가 있으면 이 문제가 훨씬 줄어듭니다 (TMAP의 POI 데이터베이스가 실제 한국 명소 이름에 대해 OpenStreetMap보다 적중률이 높습니다).

## v8: UI 다이어트 + 신뢰성 개선 + 내비 개선

1. **추측성 숫자 전부 삭제**: 통행료(순전한 추측), 주유비(전국 평균 유가 가정) 표시를 없앴습니다. 이제 화면에 보이는 숫자(거리·시간)는 전부 TMAP/OSRM 실제 도로 데이터입니다.
2. **가능 시간을 숫자 직접입력으로**: 드롭다운 대신 시간(소수점 가능, 예: 1.5)을 직접 입력합니다.
3. **추천 3개 안정적으로 채우기**: AI에게 5개 후보를 받아서, 실제 지도에서 확인되는 순서대로 3개를 채택합니다. 예전엔 1~2개만 나올 때가 있었는데 이걸로 개선됩니다.
4. **사이드바 대폭 축소**: 동행/기분/선호뷰/연료·연비/카페·주유소·주차장 옵션을 전부 삭제했습니다. 남은 건 검색창 + 출발지 + 가능시간 + 왕복/편도뿐입니다. (기분/선호뷰는 검색창에 자연어로 그대로 입력하면 AI가 인식합니다 — 예: "야경 이쁜 곳으로 가고싶어")
5. **내비게이션 개선**:
   - 카카오맵: 그대로 (API 키 없이 웹으로 바로 열림)
   - 네이버지도: 출발지 좌표까지 함께 전달해서 바로 경로가 뜨도록 변경 (`m.map.naver.com/route.nhn`)
   - TMAP: 공식 앱 URL 스킴(`tmap://route?...`)으로 전환 — **모바일에 TMAP 앱이 설치되어 있어야 열립니다.** PC 브라우저에서는 앱 전용 링크라 반응이 없을 수 있는데, 이는 브라우저의 근본적인 제약이라 코드로 해결할 수 없는 부분입니다. 실제 폰에서 테스트해보세요.
6. 주변 카페/맛집 검색은 이제 항상 자동으로 표시됩니다 (토글 제거).

## v9: 네이버 블로그 데이터 연동

1. `.env.local`에 `NAVER_CLIENT_ID` / `NAVER_CLIENT_SECRET`을 넣으면(https://developers.naver.com/apps 에서 "검색" API로 애플리케이션 등록 → 무료), AI에게 추천을 요청하기 전에 **"{현재지역} {검색어} 드라이브 코스"**로 네이버 블로그를 검색해서 상위 6개 글의 제목/요약을 AI 프롬프트에 참고자료로 함께 줍니다. AI는 이 블로그들에서 실제로 언급되는 명소를 우선적으로 활용하도록 지시받습니다.
2. 각 코스가 확정되면 그 장소명으로 다시 블로그를 검색해서, 관련 블로그 글 1개를 코스 카드와 상세 패널에 링크로 보여줍니다 ("📝 관련 블로그 후기 보기").
3. 키가 없으면 이 기능만 자동으로 빠지고 나머지는 그대로 동작합니다 (TMAP과 동일한 옵셔널 패턴).

## v10: 시간 활용 / 출발지 직접 지정 / 진짜 내비 연동 / 전문적 UI

1. **가능 시간 최대한 활용**: AI 프롬프트에 "목표 편도 이동시간"을 명시적으로 계산해서 줍니다 (왕복이면 총시간/2.5, 편도면 총시간의 70%). 예전엔 너무 가까운 곳만 추천되던 문제를 개선했습니다.
2. **출발지 직접 지정**: `/api/geocode` API를 추가해서, 출발지 입력창에 원하는 위치를 적고 Enter(또는 포커스 아웃)하면 그 위치를 실제 좌표로 변환해 출발지로 씁니다. 현재 위치 버튼(📍)을 다시 누르면 GPS로 되돌아갑니다.
3. **진짜 내비게이션 실행**: 카카오맵/네이버지도/TMAP 버튼이 이제 각 지도 앱의 **공식 앱 실행 URL 스킴**(`kakaomap://route?...`, `nmap://route/car?...`, `tmap://route?...`)을 먼저 시도합니다. 출발지(현재 위치 또는 직접 지정한 위치)와 목적지가 함께 전달되어, 모바일에 해당 앱이 깔려 있으면 **바로 턴바이턴 내비게이션이 실행**됩니다. 앱이 없거나 PC 브라우저면 1.2초 후 자동으로 웹페이지로 대체됩니다. (PC는 구조적으로 앱 전용 링크를 실행할 수 없어서, 완전한 테스트는 실제 폰에서 해보셔야 합니다.)
4. **UI를 전문 내비게이션 서비스 톤으로 리디자인**: 네이비/블루 컬러 팔레트, lucide-react 아이콘 체계로 이모지를 대체, 카드/버튼 스타일을 정돈했습니다.

## v11: 네이버 검색 API 제거 → 큐레이션 블로그 데이터로 교체

네이버 검색 API 키를 발급받지 못하는 경우를 위해, 실시간 API 호출 대신 **실제로 검색해서 확인한 인기 드라이브 코스 블로그 11개**를 코드 안에 데이터로 넣어뒀습니다 (`src/app/api/recommend/route.ts`의 `CURATED_DRIVE_BLOGS` 배열). 사용자 요청과 현재 지역을 이 데이터의 `regionKeywords`와 매칭해서, AI 참고자료 + 코스별 블로그 링크로 그대로 활용합니다. API 키도, 네트워크 호출도 필요 없어서 더 빠르고 안정적입니다.

**블로그를 더 추가하고 싶으면** `CURATED_DRIVE_BLOGS` 배열에 아래 형식으로 항목을 추가하면 됩니다:

```ts
{
  title: "글 제목",
  link: "실제 URL",
  description: "1~2문장 요약 (직접 요약해서 작성, 원문 복사 금지)",
  regionKeywords: ["지역명1", "지역명2", "관련 키워드"],
},
```

`regionKeywords`는 사용자 검색어나 현재 지역 텍스트에 포함될 만한 지명/키워드를 최대한 넉넉히 적어두면 매칭이 잘 됩니다.

이제 `NAVER_CLIENT_ID` / `NAVER_CLIENT_SECRET` 환경변수는 필요 없습니다.

## v12: 제외 조건 반영 + 모바일 위치 확인 개선

1. **"~는 싫어" 같은 제외 조건을 AI가 무시하던 문제 수정**: 프롬프트에 "사용자가 특정 지역을 배제하고 싶어하면 그 지역(및 그 안의 명소)은 절대 추천하지 말 것"이라는 규칙을 최우선 조건으로 추가했습니다.
2. **모바일에서 버튼이 안 넘어가던 문제 개선**: 페이지 진입 시 자동으로 위치 권한을 요청하는데, 모바일 브라우저는 사용자 탭 없이 이뤄진 자동 요청을 지연시키거나 막는 경우가 많습니다. 이제 위치가 아직 없을 때 안내 문구가 화면에 바로 보이고(📍 버튼을 눌러달라는 문구), "AI 추천 코스 생성"을 눌렀는데 위치가 없으면 자동으로 위치를 한 번 더 요청합니다.

## v13: 날씨 연동 / 반려동반 데이터 / 안 가본 곳 제외

친구가 만든 다른 팀의 구현을 참고해서, 저희가 시도하지 않았던 세 가지를 추가했습니다.

1. **실시간 날씨 연동** (Open-Meteo, 무료·키 불필요): 현재 위치의 날씨를 확인해서, 맑으면 뷰포인트·해변 등 야외 명소를, 비/눈/흐림이면 카페·맛집 등 실내 명소를 AI가 우선 고려하도록 프롬프트에 반영합니다. 왼쪽 패널 "Drive Assistant" 영역에 현재 날씨 배지가 표시됩니다.
2. **반려동반 여행 지원**: 검색어에 "반려견/강아지/애견/펫" 등의 단어가 있으면 자동으로 반려동반 모드로 인식합니다. 실제로 반려동반이 가능하다고 확인한 명소 목록(`PET_FRIENDLY_SPOTS`, `route.ts`)을 참고자료로 AI에게 주고, 해당 지역에 매칭되는 곳이 있으면 우선 추천합니다. 확인된 데이터가 없는 지역이면 AI가 통상적으로 반려동반이 허용되는 유형(카페/공원/산책로)을 고르되 "방문 전 확인 필요"라고 명시하도록 했습니다 — AI 추측을 사실처럼 보여주지 않기 위한 안전장치입니다.
3. **"안 가본 곳 위주로 추천"**: 내비게이션 버튼(카카오맵/네이버지도/TMAP)을 누르면 그 목적지가 브라우저(localStorage)에 자동으로 기록됩니다. 왼쪽 패널의 토글을 켜면, 이미 다녀온 곳은 AI 프롬프트에서 제외 지시하고 결과에서도 한 번 더 걸러냅니다. "기록 초기화"로 언제든 리셋할 수 있습니다.

`PET_FRIENDLY_SPOTS` 배열에 항목을 추가하면 반려동반 데이터를 더 늘릴 수 있습니다 (블로그 큐레이션과 동일한 방식).

## 1. VS Code에서 열기

압축을 풀고 VS Code에서 `drive-ai` 폴더를 여세요. (파일 → 폴더 열기)

## 2. PowerShell에서 설치 & 실행

VS Code 하단 터미널(PowerShell)에서:

```powershell
cd C:\Users\LG\Desktop\drive-ai   # 실제 압축 푼 경로로 변경
npm install
```

`.env.local.example`을 복사해서 `.env.local`을 만들고 실제 값을 채워 넣으세요.

```powershell
Copy-Item .env.local.example .env.local
notepad .env.local
```

`.env.local` 안에 최소한 이것만 채우면 됩니다:

```
OPENAI_API_KEY=sk-실제키
OPENAI_MODEL=gpt-5-mini
```

> `OPENAI_MODEL`은 https://platform.openai.com/docs/models 에서 본인 계정으로 실제 호출 가능한 모델명인지 확인하세요.
> 404 에러가 뜨면 십중팔구 이 값이 원인입니다.

실행:

```powershell
npm run dev
```

브라우저에서 http://localhost:3000 접속.

## 3. 동작 확인 순서 (문제가 또 생기면)

1. 검색창에 "바다 보러 가고 싶어" 입력 → 버튼 클릭
2. 버튼 글자가 "AI가 코스를 찾는 중..."으로 바뀌는지 확인
3. **VS Code 터미널**에 `[recommend] 요청 시작` 부터 로그가 쭉 찍히는지 확인 — 어디서 멈추는지가 원인입니다
4. 그래도 안 되면 브라우저 개발자도구(F12) → Console 탭의 빨간 에러 메시지를 확인

## 5. Vercel 배포

1. https://vercel.com 에서 GitHub 계정으로 로그인
2. "Add New… → Project" → 방금 만든 `drive-ai` 저장소 선택
3. Framework는 Next.js가 자동 인식됩니다
4. **Environment Variables**에 `.env.local`과 똑같이 입력:
   - `OPENAI_API_KEY`
   - `OPENAI_MODEL`
   - `NEXT_PUBLIC_KAKAO_JAVASCRIPT_KEY` (카카오내비 쓸 경우)
5. Deploy 클릭

이후 코드를 고치고 `git push`만 하면 Vercel이 자동으로 재배포합니다.
